# Step 3: Epic Demo Gate

## Purpose
Connect the single-epic demonstration to the broader value of applying this discipline across their entire pipeline.

## Procedure

1. **Summarise what changed:**
   - "This epic went from [X ambiguities] to [Y testable criteria]"
   - "The dependencies are now explicit — before, someone would have discovered them mid-sprint"
   - "The verification section means you'll know when this is done, not when someone feels like it's done"

2. **Scale the implication:**
   - "This is one epic. You have [estimated number based on codebase size] active across your teams."
   - "If this epic's ambiguity is typical, each one carries similar rework risk."
   - Connect to scan numbers if available: "Combined with your [X]% rework rate, structured requirements across your pipeline could recover [estimate] of engineering capacity."

3. **Deliver the gate:**

```
This is what Epic as Code looks like for one epic. The implementation
covers your entire pipeline — templates, governance rules, team training,
and integration with your existing tools.

The Federation Workshop includes Epic as Code as part of the broader
requirements-to-delivery restructuring.

→ Book a Workshop Briefing: sprantic.ai/bookings/workshop-briefing
```

4. **If they ask for more epics:** Redirect naturally.
   - "Each epic has its own context and dependencies — the value of the implementation is that your teams learn to do this themselves, with governance that ensures consistency. Want to discuss what that looks like for your organisation?"

## Done
Skill complete. The customer has seen the concept in action on their own code.
